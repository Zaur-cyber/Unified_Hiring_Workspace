# Единый кабинет найма компании X — решение кейса

Мини-дискавери, проектирование сценария и кликабельный прототип ключевого экрана для кабинета
найма, объединяющего нанимающих менеджеров, рекрутеров и HR на пути «от заявки на вакансию до
выхода сотрудника».

## Постановка

Сейчас найм рассредоточен по инструментам: заявки согласуются в почте, кандидаты ведутся в Excel, фидбэк по интервью — в чатах. Это приводит к материальным и временным издержкам, отрицательно влияет на пользовательский опыт. Решине - создание цифрового сервиса - Единый кабинет найма.

## TL;DR

- **Главный гэп** — не в самой воронке, а на стыках ролей: каждая передача (менеджер → согласующий → рекрутер → интервьюеры → HR) идёт вручную через почту или чат.
- **Ядро to-be** — один объект «Вакансия» с состоянием; согласование заявки, воронка,
структурированный фидбэк и запуск онбординга внутри системы, с автопереходами и SLA-таймерами.
- **MVP** — тонкий сквозной срез «заявка → согласование → воронка → scorecard → чек-лист
онбординга». Приоритизация — RICE с гейтом на непрерывность happy path. Аналитический дашборд
осознанно отложен.

Весь разбор кейса — в одном файле [`Единый_кабинет_найма.html`](Единый_кабинет_найма.html), разделённом на вкладки:

## Как смотреть

- **Разбор кейса** — открыть `Единый_кабинет_найма.html` в браузере, переключаться вкладками. Ссылка вида
`Единый_кабинет_найма.html#d03` открывает нужную вкладку сразу. При печати в PDF (Chrome → «Сохранить как
PDF», A4) все вкладки разворачиваются, каждая с новой страницы. Единственная внешняя
зависимость — шрифты Google Fonts; без сети подставляются системные, вёрстка не ломается.
- **Прототип** — двойной клик по `prototype/index.html` *либо публикация через GitHub Pages
(Settings → Pages →* `main` */ root), далее* `/<repo>/` *для разбора и* `/<repo>/prototype/` *для протот*ипа.



## Прототип — сквозной флоу «от заявки до оффера»

Кликабельная модель кабинета найма: 6 связанных экранов в одном файле `prototype/index.html`, без
сборки и зависимостей (vanilla HTML/CSS/JS). Состояние живёт в памяти вкладки, данные моковые.
Тёмная тема подхватывается из настройки ОС.


| #   | Экран                  | Роль                | Что показывает                                                                                            |
| --- | ---------------------- | ------------------- | --------------------------------------------------------------------------------------------------------- |
| 1   | **Заявка на вакансию** | нанимающий менеджер | Форма с обязательными полями; маршрут согласования зависит от вилки (порог 350к → подключается C&B)       |
| 2   | **Согласование**       | согласующий         | Карточка заявки, пошаговый маршрут, «Согласовать» / «Отклонить» с причиной                                |
| 3   | **Карточка вакансии**  | рекрутер            | Данные перенесены из заявки, команда найма, сводка воронки, «Опубликовать»                                |
| 4   | **Воронка**            | рекрутер + HM       | Канбан по этапам, счётчики, индикатор превышения SLA                                                      |
| 5   | **Карточка кандидата** | рекрутер            | История, блок фидбэка интервью, scorecard-модалка, агрегат рекомендаций                                   |
| 6   | **Оффер**              | рекрутер            | Условия в рамках согласованной вилки (выход за неё блокируется), отправка, принятие → чек-лист онбординга |


Шаги переключаются кнопками действий и кликом по индикатору сверху.

**Демо-путь:**

1. **Заявка** → «Отправить на согласование».
2. **Согласование** → «Согласовать текущий шаг» дважды (HM, затем C&B) → создаётся карточка вакансии.
3. **Вакансия** → «Опубликовать вакансию» → «Открыть воронку».
4. **Воронка** → открыть «Игорь Волков» (этап «Фидбэк»).
5. **Кандидат** → «Оценить» у двух ожидающих интервьюеров → заполнить scorecard → смотреть агрегат →
  «Оформить оффер» (кнопка активна только когда фидбэк собран — правило S3.5).
6. **Оффер** → задать условия → «Отправить оффер» → «Отметить принятым» → появляется чек-лист онбординга.
